# assay-anchors

[Assay](https://github.com/) 不可修改日誌的錨點紀錄。**這個 repo 是公開的。**

每一行是某個時間點日誌鏈頭的雜湊：

| 欄位 | 意義 |
|------|------|
| `anchored_at` | 錨定當下的 UTC 時間 |
| `date` | 錨定日期 |
| `seq` | 當時日誌的最後一筆序號 |
| `n_entries` | 當時日誌的總筆數 |
| `head_hash` | 當時鏈頭的 SHA-256 |

**這裡沒有任何一筆紀錄的內容。** 沒有標的、沒有部位、沒有預測、沒有理由。
雜湊是單向的，反推不出原始內容。

## 這個 repo 的用途

日誌本身放在私人的程式碼 repo，本機的雜湊鏈只能證明「鏈內部自洽」——
有檔案權限的人可以把整條鏈重算一遍，重算後一樣自洽。

把鏈頭雜湊推到這裡，重算過的鏈就會跟已經公開的歷史對不上。
**前提是這個 repo 要開分支保護、禁止強制推送**，否則歷史一樣能被改寫。

## 已知的重複紀錄（不會修掉）

檔案裡有兩對完全重複的錨點，`seq` 與 `head_hash` 都一樣：

| 行 | seq | 日期 | 原因 |
|----|-----|------|------|
| 1、2 | 2 | 2026-09-21 | 開發過程中手動連跑兩次 `anchor` |
| 3、4 | 11 | 2026-09-22 | launchd 的 `RunAtLoad` 載入時跑一次，
之後手動 `launchctl kickstart` 又跑一次 |

原因是**錨定程式當初不是冪等的**：不管鏈頭有沒有變，每次執行都會
附加一行並產生一個 commit。已於 2026-09-22 修正——
現在如果最新一筆錨點的 `seq` 和 `head_hash` 與目前日誌相同，
就會印出「鏈頭未變，略過」，不寫入也不 commit。

**這幾行不會被刪除或修改。** 這個 repo 的意義就在於歷史不能被改寫，
為了讓紀錄好看一點而回頭改，跟這整套機制要防的事情是同一件。

重複的錨點不會讓驗證出錯（驗證比對的是「某個 seq 對應的雜湊」），
但它會讓「錨點數量」這個數字失去意義——看起來錨了很多次，
其實只錨到同一個狀態。

## 不要手動編輯

這個檔案只能由 `python -m assay.journal.cli anchor --push` 附加。
手動改任何一行，都會讓之前所有的錨定失去意義。
